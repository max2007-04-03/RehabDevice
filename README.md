# 🏥 RehabDevice — Автономна медична ІоТ-система моніторингу реабілітації кисті (ESP32)

**RehabDevice** — це професійний автономний медико-інженерний IoT-комплекс на базі мікроконтролера **ESP32** та 6-осьового інерційного датчика **MPU6050 / MPU6500 (GY-521)**. Система призначена для точного відстеження рухомості суглобів кисті в реальному часі, автоматичного визначення плавности/тремору, збору розширеної клінічної аналітики, а також **гейміфікації процесу реабілітації**.

Весь користувацький веб-інтерфейс (UI), медичні показники, інтерактивні підказки, ігровий модуль, модальні вікна та експортовані CSV-звіти працюють **виключно українською мовою** 🇺🇦 з урахуванням сучасної медичної термінології та клінічних вимог.

Пристрій є повністю незалежним від зовнішнього інтернету: він створює власну Wi-Fi точку доступу (`RehabDevice_AP`) з підтримкою **Captive Portal** (автоматичне спливаюче вікно авторизації на iOS та Android при підключенні) і зберігає всю історію тренувань у вбудованій флеш-пам'яті чипа (`LittleFS`) за допомогою високоефективної архітектури потокового доступу.

## 🎮 1. Гейміфікація реабілітації (Smart Bot)

Система включає потужний модуль ігрової терапії, який перетворює нудне повторення медичних вправ на захопливий процес!

* **Вбудована гра «Пінг-понг»:** Пацієнт керує ракеткою виключно за рахунок рухів власної кисті (через гіроскоп та акселерометр). Це спонукає його досягати крайніх кутів амплітуди.
* **Smart Bot (Розумний супротивник):** Унікальний алгоритм бота, який підлаштовується під пацієнта. 
* **Рівні складності:**
  * **🤖 Авто-терапія (Адаптивна):** Бот автоматично адаптує свою швидкість і стиль гри під поточні можливості пацієнта (його амплітуду та плавність), стимулюючи легкий прогрес.
  * **🟢 Легкий, 🟡 Середній, 🔴 Складний:** Режими для різних стадій відновлення.
* Всі ігрові обчислення виконуються прямо у веб-браузері з частотою оновлення ~30 FPS, спираючись на безперебійний WebSocket-стрімінг з мікроконтролера.

## 🛠 2. Апаратне підключення (Розпіновка)

Для складання пристрою використовується плата **ESP32 DevKit** (чип ESP-WROOM-32), модуль гіроскопа/акселерометра **GY-521 (MPU-6050 / MPU-6500)** та **MicroSD Card Adapter**.

### 2.1. Підключення гіроскопа (GY-521)

| Вивід датчика (GY-521) | Пін ESP32 | Опис призначення |
| :--- | :--- | :--- |
| **VCC** | **3V3** (3.3V) | Живлення датчика |
| **GND** | **GND** | Спільна земля |
| **SCL** | **GPIO 22** | Лінія тактування апаратної шини I2C |
| **SDA** | **GPIO 21** | Лінія даних апаратної шини I2C |
| **INT** | **GPIO 17** | Апаратне переривання готовності пакетів DMP |
| **AD0** | **GND** | Притягнути до землі для фіксації I2C-адреси `0x68` |

### 2.2. Підключення SD-карти (SPI)

| Вивід SD-модуля | Пін ESP32 | Опис призначення (VSPI) |
| :--- | :--- | :--- |
| **VCC** | **5V (VIN)** | Живлення модуля (більшість модулів мають стабілізатор 5V -> 3.3V) |
| **GND** | **GND** | Спільна земля |
| **MISO** | **GPIO 19** | Master In Slave Out |
| **MOSI** | **GPIO 23** | Master Out Slave In |
| **SCK** | **GPIO 18** | Serial Clock (такти шини) |
| **CS** | **GPIO 5** | Chip Select (вибір пристрою) |

> [!IMPORTANT]  
> **Стабільність живлення (Обов'язково!)**  
> При одночасній роботі передавача Wi-Fi та записі на SD-карту напруга на USB може просідати, що призводить до зависання датчиків (`I2C Error 263` або перезавантаження SD).  
> **Рішення:** Встановіть електролітичний конденсатор на **470 мкФ (10V-16V)** безпосередньо в шину живлення на макетній платі (довга ніжка до `5V/VIN`, коротка з білою смугою до `GND`). Для додаткової фільтрації I2C-помех рекомендується встановити керамічний конденсатор **0.1 мкФ (104)** паралельно живленню гіроскопа.

## 📂 3. Встановлення та налаштування (PlatformIO)

Проєкт був повністю переведений на професійне середовище розробки **PlatformIO**. Вам більше не потрібно шукати та встановлювати бібліотеки вручну!

### Крок 1. Підготовка середовища
1. Встановіть [Visual Studio Code (VSCode)](https://code.visualstudio.com/).
2. У VSCode відкрийте вкладку Extensions (Розширення) та встановіть **PlatformIO IDE**.
3. Натисніть `File -> Open Folder` і виберіть теку з цим проєктом (`esp32dev-RehabDevice`).

### Крок 2. Автоматичне завантаження залежностей
PlatformIO автоматично прочитає файл `platformio.ini` та завантажить найсвіжіші та найстабільніші версії бібліотек:
- **`ArduinoJson`** (v7.4.3)
- **`ESPAsyncWebServer`** (v3.12.0)
- **`MPU6050`** (v1.4.5 від ElectronicCats)

---

## 🚀 4. Як прошити та запустити комплекс

У лівій панелі VSCode натисніть на іконку "інопланетянина" (PlatformIO), розгорніть меню `Project Tasks -> esp32dev_RehabDevice`:

1. **Прошивка коду (C++):** 
   * Перейдіть у `General` і натисніть **Upload**. Зачекайте завершення прошивки мікроконтролера.
2. **Прошивка веб-інтерфейсу (LittleFS):** 
   * Перейдіть у `Platform` і натисніть **Build Filesystem Image**.
   * Потім натисніть **Upload Filesystem Image** *(Важливо: перед цим кроком закрийте Serial Monitor, інакше порт буде зайнятий!)*.
3. **Запуск:**
   * Підключіться з телефону або комп'ютера до Wi-Fi мережі **`RehabDevice_AP`** (пароль: **`rehab1234`**).
   * Відкриється автоматичне вікно Captive Portal, або перейдіть вручну за адресою **`http://192.168.4.1`**.

## 🏗 5. Сучасна інженерна архітектура системи

Код проєкту побудований за принципом промислових систем реального часу і розділений на 4 незалежні асинхронні модулі (тепер сумісні з новітнім стандартом ArduinoJson v7):

### 🔹 1. Підсистема сенсорики (`SensorMPU.cpp`)
* Використовує апаратний блок **DMP** (Digital Motion Processor). Це дозволяє отримувати ідеально точні кути (Pitch, Roll, Yaw) без завантаження ядра ESP32.
* Зчитування по I2C (400 кГц) виконується по перериванню (`GPIO 19`), що робить систему неблокуючою.
* Підтримується миттєве рекалібрування "на льоту".

### 🔹 2. Клінічний аналітичний рушій (`AnalyticsEngine.cpp`)
* **Амплітуда:** Точна фіксація кутових меж руху.
* **Плавність (Smoothness) та Тремор:** Диференціювання кутового прискорення для фіксації ривків (поріг `180.0 deg/s^2`).
* **Згинання (Flexions):** Подвійний гістерезис для ігнорування фізіологічного тремору рук.
* **Утримання (Holding Time):** Фіксація часу в крайніх точках.

### 🔹 3. Zero-Copy Streaming та MemoryFS (`MemoryFS.cpp`)
* Пацієнт-центричне сховище у форматі **JSONL** з використанням швидкодіючого **Murmur/FNV-1a хеш-індексу**.
* Генератор чанків видає історію сесій без переповнення пам'яті (~1.5 КБ RAM). 

### 🔹 4. WebServerModule та WiFiManagerModule
* Двосторонній WebSocket-зв'язок (~30 FPS) для ігор та візуалізації реального часу.
* Повний Captive Portal DNS для перенаправлення на локальний веб-інтерфейс.

## 🖥 6. Можливості веб-інтерфейсу

* **Вкладка «Пацієнт (Тренування)»:**
  * Інтерактивне коло для візуалізації поточного кута нахилу.
  * Панель запуску ігор (Гейміфікація), вибір складності бота.
  * Живі метрики сесії (кут, амплітуда, кількість згинань).
* **Вкладка «Кабінет Лікаря»:**
  * **Smart Search:** Швидкий пошук пацієнтів та фільтрація сесій.
  * **Zero-Squish Charting:** Прокручувані графіки на `Chart.js` (або резервний HTML5 Canvas рушій при відсутності інтернету).
  * **CSV Експорт:** Завантаження всієї статистики у форматі Excel (`uFEFF` UTF-8 BOM).
  * **Безпечні модальні вікна:** Замінюють системні alert/confirm, які блокуються у Captive Portal (Android/iOS).
