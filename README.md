# 🏥 RehabDevice — Автономна медична ІоТ-система моніторингу реабілітації кисті (ESP32)

**RehabDevice** — це професійний автономний медико-інженерний IoT-комплекс на базі мікроконтролера **ESP32** та 6-осьового інерційного датчика **MPU6050 / MPU6500 (GY-521)**. Система призначена для точного відстеження рухомості суглобів кисті в реальному часі, автоматичного визначення плавности/тремору, збору розширеної клінічної аналітики, а також **гейміфікації процесу реабілітації**.

Весь користувацький веб-інтерфейс (UI), медичні показники, інтерактивні підказки, ігровий модуль, модальні вікна та експортовані CSV-звіти працюють **виключно українською мовою** 🇺🇦 з урахуванням сучасної медичної термінології та клінічних вимог.
Водночас усі **системні лоґи (`Serial` та `console.log`) та інженерні коментарі у вихідному коді C++/JavaScript/CSS** стандартизовані та виконані **англійською мовою (English)** 🇬🇧 відповідно до найкращих практик інженерної розробки та підтримки вбудованих систем.

Пристрій є повністю незалежним від зовнішнього інтернету: він створює власну Wi-Fi точку доступу (`RehabDevice_AP`) з підтримкою **Captive Portal** (автоматичне спливаюче вікно авторизації на iOS та Android при підключенні) і зберігає всю історію тренувань у вбудованій флеш-пам'яті чипа (`LittleFS`) за допомогою високоефективної архітектури потокового доступу.

## 🎮 1. Новітнє оновлення: Гейміфікація реабілітації (Smart Bot)

Нова версія системи включає потужний модуль ігрової терапії, який перетворює нудне повторення медичних вправ на захопливий процес!

* **Вбудована гра «Пінг-понг»:** Пацієнт керує ракеткою виключно за рахунок рухів власної кисті (через гіроскоп та акселерометр). Це спонукає його досягати крайніх кутів амплітуди.
* **Smart Bot (Розумний супротивник):** Унікальний алгоритм бота, який підлаштовується під пацієнта. 
* **Рівні складності:**
  * **🤖 Авто-терапія (Адаптивна):** Бот автоматично адаптує свою швидкість і стиль гри під поточні можливості пацієнта (його амплітуду та плавність), стимулюючи легкий прогрес.
  * **🟢 Легкий, 🟡 Середній, 🔴 Складний:** Режими для різних стадій відновлення.
* Всі ігрові обчислення виконуються прямо у веб-браузері з частотою оновлення ~30 FPS, спираючись на безперебійний WebSocket-стрімінг з мікроконтролера.

## 🛠 2. Апаратне підключення (Розпіновка датчика GY-521)

Для складання пристрою використовується плата **ESP32 DevKit** (чип ESP-WROOM-32) та модуль гіроскопа/акселерометра **GY-521 (MPU-6050 / MPU-6500)**.

| Вивід датчика (GY-521) | Пін ESP32 | Опис призначення |
| :--- | :--- | :--- |
| **VCC** | **3V3** (3.3V) | Живлення датчика (рекомендується стабільна напруга 3.3V від плати ESP32) |
| **GND** | **GND** | Спільна земля |
| **SCL** | **GPIO 22** | Лінія тактування апаратної шини I2C |
| **SDA** | **GPIO 21** | Лінія даних апаратної шини I2C |
| **INT** | **GPIO 19** | Апаратне переривання готовності пакетів сопроцесора DMP (Digital Motion Processor) |
| **AD0** | **GND** | Притягнути до землі для фіксації I2C-адреси `0x68` |

## 📂 3. Встановлення бібліотек та налаштування Arduino IDE 2.x

### Крок 1. Обов'язкові бібліотеки (Library Manager)
Відкрийте **Arduino IDE 2.x**, натисніть `Ctrl + Shift + I` (Менеджер бібліотек) та встановіть такі версії:

1. **`ArduinoJson`** (версія **`7.4.3`** або новіша) — серіалізація чанків та збереження метаданих.
2. **`Async TCP`** (версія **`3.4.10`** або новіша) — асинхронний мережевий стек.
3. **`ESP Async WebServer`** (версія **`3.11.2`** або новіша) — асинхронний HTTP-сервер та WebSocket.
4. **`MPU6050`** (версія **`1.3.1`** або новіша, автор: Electronic Cats) — робота з DMP.

### Крок 2. Плагін для завантаження файлової системи (`LittleFS Filesystem Uploader`)
Всі файли веб-інтерфейсу (включно з новою текою `/games/pingpong/`) прошиваються у внутрішню пам'ять чипа:
1. Завантажте `.vsix` плагін: [arduino-littlefs-upload](https://github.com/earlephilhower/arduino-littlefs-upload/releases).
2. Скопіюйте у директорію плагінів Arduino IDE.
3. Використовуйте команду **`Upload LittleFS to Pico/ESP8266/ESP32`** у палітрі команд (`Ctrl + Shift + P`).

### Крок 3. Налаштування плати
* **Плата:** `ESP32 Dev Module`
* **Схема розділів:** `Default 4MB with spiffs` або `Huge APP` *(обов'язково з FS)*.
* **Швидкість завантаження:** `921600`.

## 🚀 4. Як прошити та запустити комплекс

1. Завантажте C++ прошивку (`RehabDevice.ino` -> `Ctrl + U`).
2. Прошийте веб-інтерфейс через LittleFS плагін (переконайтесь, що Serial Monitor закритий).
3. Підключіться до Wi-Fi мережі **`RehabDevice_AP`** (пароль: **`rehab1234`**).
4. Відкриється автоматичне вікно Captive Portal, або перейдіть за адресою **`http://192.168.4.1`**.

## 🏗 5. Новітня інженерна архітектура системи

Код проєкту побудований за принципом промислових систем реального часу і розділений на 4 незалежні асинхронні модулі:

### 🔹 1. Підсистема сенсорики (`SensorMPU.cpp`)
* Використовує апаратний блок **DMP** (100 Гц).
* Зчитування по I2C (400 кГц) по перериванню (`GPIO 19`).
* Підтримується миттєве рекалібрування 0° на льоту.

### 🔹 2. Клінічний аналітичний рушій (`AnalyticsEngine.cpp`)
* **Амплітуда:** Точна фіксація кутових меж.
* **Плавність (Smoothness) та Тремор:** Диференціювання кутового прискорення для фіксації ривків (поріг `180.0 deg/s^2`).
* **Згинання (Flexions):** Подвійний гістерезис для ігнорування фізіологічного тремору рук.
* **Утримання (Holding Time):** Фіксація часу в крайніх точках.

### 🔹 3. Zero-Copy Streaming та MemoryFS (`MemoryFS.cpp`)
* Пацієнт-центричне сховище у форматі **JSONL** з використанням **Murmur/FNV-1a хеш-індексу**.
* Генератор чанків (`streamSessionsToCallback`) видає історію сесій без переповнення пам'яті (~1.5 КБ RAM). Швидкість до 4500 записів/с!

### 🔹 4. WebServerModule та WiFiManagerModule
* Captive Portal DNS для автопідключення.
* Двосторонній WebSocket-зв'язок (~30 FPS) для ігор та візуалізації.

## 🖥 6. Можливості веб-інтерфейсу

* **Вкладка «Пацієнт (Тренування)»:**
  * Інтерактивне коло для візуалізації.
  * Панель запуску ігор (Гейміфікація), вибір складності бота.
  * Живі метрики сесії (кут, амплітуда, кількість згинань).
* **Вкладка «Кабінет Лікаря»:**
  * **Smart Search:** Швидкий пошук пацієнтів та фільтрація сесій.
  * **Zero-Squish Charting:** Прокручувані графіки на `Chart.js` (або резервний HTML5 Canvas рушій при відсутності інтернету).
  * **CSV Експорт:** Завантаження всієї статистики у форматі Excel (`uFEFF` UTF-8 BOM).
  * **Безпечні модальні вікна:** Замінюють системні alert/confirm, які блокуються у Captive Portal (Android/iOS).
